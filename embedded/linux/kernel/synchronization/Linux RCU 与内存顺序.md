# Linux RCU 与内存顺序

> RCU 主要让读者在并发更新期间安全访问对象；锁、引用计数和内存屏障各解决不同的问题。

## TL;DR

- `rcu_read_lock()` 保护受 RCU 管理的读侧临界区；发布与读取指针使用相应的 RCU 接口。
- 删除对象先让新读者无法找到它，再等待宽限期或安排 RCU 回调，最后释放；普通 RCU 不替写者串行化。
- 自旋锁 / mutex 保护共享状态，引用计数延长对象寿命，RCU 管理读侧并发与回收；不能互相替代。
- 编译器重排、CPU 重排、DMA 缓存同步和 MMIO 顺序是不同问题，选择各自的接口。

适用范围：Linux 6.18 LTS。

## 常见模式

| 目标 | 常用机制 | 边界 |
| --- | --- | --- |
| 短临界区、不可睡眠上下文共享状态 | 自旋锁 | 注意中断上下文、锁顺序及 PREEMPT_RT 语义 |
| 可睡眠的互斥过程 | mutex | 不能在硬中断或禁止睡眠的上下文中使用 |
| 读多写少且允许延迟回收 | RCU | 写侧仍需同步；读侧取出的指针不能无条件带出保护范围 |
| 等待一次完成或可重复检查的条件 | completion / wait queue | 超时、取消和对象释放是独立步骤 |

典型 RCU 生命周期：写者初始化新对象后发布指针；读者在读侧临界区取得并使用对象；写者移除旧对象后，使用适合上下文的宽限期等待或回调回收。对象若需在读侧临界区外继续使用，还需在受保护时安全获取有效引用。

## 发布、读取与回收

```text
写者：初始化新对象 → 同步其他写者 → 发布新指针 → 延迟回收旧对象
读者：进入 RCU 读侧 → 读取受保护指针 → 使用对象 → 退出读侧
```

写者使用 `rcu_assign_pointer()` 发布已初始化的对象；读者在适当的 RCU 读侧临界区使用 `rcu_dereference()` 取得指针。RCU 提供访问与回收所需的顺序关系，但不自动串行化多个写者，也不保证读者看到正在原地修改的多个字段构成一致快照。需要一致性时设计不可变替换、锁或其他协议。

移除旧对象之后，可通过 `synchronize_rcu()` 等待相应宽限期，或通过 `call_rcu()` 安排回调。宽限期确保相关的既有读侧临界区结束；普通 RCU 读侧不应主动进行阻塞等待。回收回调不能依赖可睡眠上下文；模块卸载时还要保证自己的回调已完成，不能仅释放模块代码。

如果读者需要在退出 RCU 读侧后保留对象，应在对象仍受到保护时通过适当的引用获取协议取得引用；“先退出读侧、再对旧指针加引用”存在对象已被释放的竞态。

## 内存顺序的边界

| 机制 | 能解决什么 | 不能单独解决什么 |
| --- | --- | --- |
| `READ_ONCE()` / `WRITE_ONCE()` | 约束指定访问的编译器处理 | 多字段一致性、互斥、对象寿命 |
| acquire / release 或锁 | 建立对应访问间的顺序与可见性 | 设备 DMA 映射或硬件 I/O 语义 |
| RCU 读写接口 | 安全发布指针及延迟回收 | 任意可变字段的并发修改 |
| DMA / MMIO 接口 | 按设备和平台契约处理访问 | 自动代替普通内存数据结构的同步 |

内存屏障约束的是访问顺序，不自动提供互斥、等待或对象寿命。`READ_ONCE()` / `WRITE_ONCE()` 不等同于完整锁；设备寄存器使用 MMIO 访问器，设备 DMA 缓冲区按 DMA API 的所有权规则同步。锁和 DMA 细节分别见 [[Kernel API - spin_lock_irqsave]] 与 [[Kernel API - dma_map_single]]。

## 更新和卸载时的检查

1. 写者先完整初始化新对象，在写侧保护下替换共享指针；不能先发布、后补齐读者必须看到的字段。
2. 旧对象不再对新读者可见后，等待 RCU 宽限期或排队回收回调；等待期间旧读者仍可能访问它。
3. 回调若使用对象中嵌入的 `rcu_head`，该对象必须保留到回调真正运行；仅调用 `call_rcu()` 并不表示已释放。
4. 模块卸载前停止产生新回调，并使用适当的回调完成同步机制；仅等待一个宽限期不等于所有已经排队的回调都已执行。

`rcu_barrier()` 用于等待此前已排队的 RCU 回调完成；它不代替阻止新的调用方、线程或设备事件。读侧和写侧使用的具体 RCU 变体必须配套，不要混用普通 RCU 与 SRCU 的保护 / 回收接口。
