# RTL8822CE TXBD 调试备份的开销与关闭方式

> 已将上游 `3a28689bd`、`409968622` 成对纳入源码：关闭默认开启的 TXBD 备份，
> 并保护调试函数调用。同配置模块编译通过，`.bss` 减少 8968 B，strip 后文件减少 10640 B。
> 旧模块运行态 A/B：每个 1200 B UDP 数据报的系统开销差值中位数为约 **5.41 µs**，
> 六组范围 **5.07–6.30 µs**，按各核时钟折算；这不是包延迟或最大吞吐收益。
> 工程机已启动含补丁的 `#14` 并通过 Wi-Fi SSH 通信；补丁版吞吐与功耗尚未重测。
> 这两项修改不配置 Wi-Fi / 蓝牙唤醒；唤醒条件见 [独立专题](rtl8822ce-wakeup.md)。

## 方法

正式关闭发生在编译期：`include/autoconf.h` 不再定义 `DBG_TXBD_DESC_DUMP`，
`hal/rtl8822c/rtl8822c_ops.c` 的 `core_get_tx_ring_ext()` 调用由同一宏保护。
两项必须一起应用；否则调试声明、实现已被裁掉，调用仍会进入编译。

旧模块可用现有 proc 开关做同模块 A/B；须先核对实际接口，优先使用独立的有线管理链路：

```sh
# 仅适用于仍编入 TXBD 调试的旧模块；不读写其他寄存器诊断节点。
printf '0 0\n' | sudo tee /proc/net/rtl88x2ce/wlan0/tx_ring_ext >/dev/null
printf '1 0\n' | sudo tee /proc/net/rtl88x2ce/wlan0/tx_ring_ext >/dev/null
```

第一列 `0` 关闭、`1` 开启，第二列 `0` 保留缓冲区；不要用 `2`，它会触发测试 dump。
开关属于各虚拟接口，备份数组由模块共享。计时窗口内不读取 `tx_ring_ext`，
因为读取会输出 ring 并持有发送锁；每轮在窗口外确认模式未进入 HALT，结束恢复原状态。
运行态 OFF 仍保留分支和静态缓冲区，不能代替新模块的全部编译期效果。

## 原因

调试位初值为 `DUMP_TXBD_ON`，正常发送也会执行备份。
在 `rtl8822ce_dump_xframe()` 的 `nr_frags` 循环内，每个提交的 **802.11 分片**增加：

| 操作 | 成本 |
| --- | --- |
| TX DMA 状态、队列读写指针查询 | 两次 32 位 PCIe MMIO 读取 |
| TXBD、TX descriptor、数据头备份 | 三次 `memcpy`，分别 20 / 48 / 30 B，共 98 B |
| 缓冲区记账 | 指针、长度、状态存储和环形索引更新 |

上述工作位于 `irq_th_lock` 临界区内。802.11 分片、UDP 数据报和无线重传不是同一计数单位。
`rtw_tx_desc_backup()` 仅包含后一次寄存器读取及备份，单独测它会漏掉外层状态读取。
关闭调试后，正常错误计数及自复位路径仍保留。

## 证据

### 补丁版加载核对

2026-10-23 工程机 LubanCat-5 V2 从 eMMC 启动 `6.1.172 #14`，
`linux-image-6.1.172` / headers 均为 `6.1.172-14`，内核包文件校验无差异、taint=0。
已加载 `8822ce` 与安装文件的 `srcversion` 均为 `EB08C10553079BD3C5EBB27`，
SSH 管理连接通过该驱动的 `p2p0` Wi-Fi 接口。本轮没有重载模块、主动压测或改动无线配置；
仅证明补丁版已加载并能维持既有通信，不代替下述旧模块 A/B，也不证明性能提升。

### 同配置编译与尺寸

2026-10-23，在编译服务器的独立驱动副本上，使用运行内核 `6.1.172 #13` 的完整构建树、
配置、`Module.symvers` 和 GCC 13.3，分别编译原版、补丁版 `8822ce.ko`。
两副本路径等长，避免驱动内 `__FILE__` 字符串长度影响比较。

| ELF 部分 | 原版 / B | 补丁版 / B | 减少 / B |
| --- | ---: | ---: | ---: |
| `.text*` | 1429229 | 1425377 | 3852 |
| `.rodata*` | 574139 | 573466 | 673 |
| `.data*` | 234291 | 234291 | 0 |
| `.bss` | 39512 | 30544 | 8968 |
| strip 后模块文件 | 3650760 | 3640120 | 10640 |

两次构建退出 0，无编译警告；外部符号集合一致，均存在于 `#13` 的 `Module.symvers`。
vermagic 均为 `6.1.172 SMP mod_unload modversions aarch64`。
旧模块 `tx_backup` 为 8960 B、`backup_idx` 为 8 B，新模块均不再包含这些符号。
这些是文件 / 静态数据尺寸，不能直接换算为 CPU 时间或吞吐收益。

### 板上运行态 A/B

LubanCat-5 V2、Mini-PCIe RTL8822CE、eMMC、`6.1.172 #13`，发包走已关联的 `wlan0`，信道 165 / 20 MHz。
计数窗口内不做 SSH 轮询；进度从接收端观察，板上结果在测试结束后取回。
大小核使用既有 performance 策略，测量不修改频率、MAC、路由、关联配置或服务。
固定负载为 2000 UDP 数据报/s、每报 1200 B，发送线程固定 CPU4；每 16 报按绝对时间节拍发送。
每轮 16000 报，名义有效载荷 19.2 Mbps，按 ON/OFF/OFF/ON 顺序重复三组，共 12 轮。
计数从启动发送程序前开始，到远端应用收齐全部唯一序号并返回一条确认、发送程序退出后结束。
正式轮次 `300–311` 的发送至确认时间为 8.000–8.010 s，PMU 窗口约 8.003–8.013 s。

主指标为每 CPU 硬件 PMU cycles / instructions，窗口内包含用户和内核、排除 hypervisor，
核对 `time_enabled == time_running`，不使用多路复用估算值。
按各 CPU 频率分别将 cycles 折算为 CPU 时间后求和，不能将大小核总 cycles 除以同一个频率。
每轮前后均核对频率：CPU0–3 为 1.8 GHz、CPU4–5 为 2.304 GHz、CPU6–7 为 2.352 GHz；
温度约 33.3–34.2 °C。频率未连续采样，折算值是估算量，不是调度器记账时间。
`/proc/stat` 在当前 tick accounting 配置下会漏记短工作，不能用于这里的精确开销结论。
`/proc/schedstat` 的非 idle 运行纳秒仅作补充，不能完整覆盖 idle 上的 IRQ 工作。

12 轮均发送并收到 **16000 报**，重复、发送错误均为 0；模式保持预期值，无 PMU 多路复用。
每种状态各六轮，以下为系统全核计数的中位数及最小–最大值：

| 指标 / 每轮 | 调试 ON | 调试 OFF |
| --- | ---: | ---: |
| CPU cycles / 百万 | 565.58（555.30–590.25） | 366.46（355.81–378.50） |
| instructions / 百万 | 330.49（329.22–342.54） | 326.76（324.04–330.02） |
| 时钟折算 CPU 时间 / ms | 249.81（244.36–261.84） | 162.70（157.63–169.29） |

每四轮中配对相邻 ON/OFF，六个 ON−OFF 差值均为正：cycles 差值中位数 **1.989 亿**，
时钟折算差值 **86.60 ms / 16000 报**，范围 81.06–100.75 ms。
按应用包归一化为约 **12430 cycles / 报**、**5.41 µs / 报**（5.07–6.30 µs）；
在名义 2000 报/s 下折算约 **1.08 个单核 CPU 百分点**。三个 ABBA 区组的差值也均为正。
六对属于固定次序的描述统计，不能当成六个独立随机样本或置信区间。

该差值包含系统背景活动、发送与确认处理及链路重试变化，是此板、此负载下的系统级观测，
不能解释成单个函数耗时、每个 802.11 分片成本或纯驱动 CPU 时间。
远端确认也不证明本机所有 TX completion / tasklet 已静默。
固定负载试验不测最大吞吐能力，运行态 OFF 也不等于编译移除后的最终收益。

`tx_stat` 是主动请求的读后清除报告，每轮前清历史、后读一次，且在 PMU 窗口外操作；
不能将前后输出当累计计数器相减。正式轮次的固件 retry 报告为 1067–2278，
success 报告为 15905–15959，不能代替接收端 16000 个应用包的独立核对。

原始每核计数、频率、包数、固件报告、编译尺寸及统计保存在
[测量数据](../assets/rtl8822ce-txbd-cost/measurements.json)。其中探索轮次 `200–211`
在发送程序完成提交时即停表，遗漏远端送达尾段，且有两轮发送阻塞；全部保留，未用于上述成本估算。
正式测量结束后程序退出 0，实读 `dump_txbd_desc=1`，发送与接收后台任务均已退出。
