既然我们已经了解了泛型的定义，现在来看看如何给这些泛型“立规矩”，这就是 **特性约束 (Trait Bounds)** 🔗。

在编写泛型代码时，你经常会发现自己需要泛型类型具备某种特定的功能。

### 2.1 为什么需要约束？

假设我们要写一个简单的函数，返回两个值中较大的那一个：

```rust
fn largest<T>(list: &[T]) -> &T {
    let mut largest = &list[0];

    for item in list {
        if item > largest { // ❌ 报错！
            largest = item;
        }
    }
    largest
}
```

这段代码无法编译。编译器会抗议：“嘿！我不确定 `T` 能不能进行大小比较。” 毕竟，不是所有的类型（比如一个空的结构体）都能用 `>` 来对比。

### 2.2 使用 Trait Bounds

为了解决这个问题，我们需要约束 `T` 必须实现了 `PartialOrd` 这个特性（Trait），它是 Rust 中专门负责大小比较的接口。

语法如下：

- **写法 A（直接约束）**: `fn largest<T: PartialOrd>(list: &[T]) -> &T`
    
- **写法 B（where 子句）**:

```rust
fn largest<T>(list: &[T]) -> &T 
where T: PartialOrd 
{ ... }
```

### ✍️ 练手时间

假设我们想写一个函数 `print_it<T>(item: T)`，它的功能是把 `item` 打印到屏幕上。

在 Rust 中，只有实现了 `std::fmt::Display` 特性的类型才能用 `{}` 打印。

**你觉得下面这段代码应该怎么补全，才能通过编译呢？**

```rust
use std::fmt::Display;

fn print_it<T: _______>(item: T) {
    println!("{}", item);
}
```

（只需填入缺失的 Trait 名称即可）

> std::fmt::Display

完全正确！填入 `Display` 之后，编译器就放心了，因为它确信无论你传入什么 `T`，它都知道该如何将其格式化为字符串。

### 2.3 多个约束 (Multiple Bounds)

有时候，你需要的规矩不止一条。比如，你既想让这个类型能**打印**，又想让它能**比较**。我们可以使用 `+` 符号来连接多个特性：

```rust
fn compare_and_print<T: Display + PartialOrd>(a: T, b: T) {
    if a > b {
        println!("Greater: {}", a);
    } else {
        println!("Smaller or Equal: {}", b);
    }
}
```

### 2.4 更加优雅的 `where` 子句

当你的泛型参数变多，或者每个参数的约束都很长时，函数签名会变得非常臃肿，像一堵墙一样：

```
// 这样写太乱了
fn some_function<T: Display + Clone, U: Clone + Debug>(t: T, u: U) -> i32 { ... }
```
