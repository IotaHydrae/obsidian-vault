# Linux 蓝牙协议栈与排查

> 蓝牙问题先分开控制器、主机协议栈和应用服务；BLE 广播、连接、配对、加密及 GATT 操作是不同阶段。

## TL;DR

- 先确认控制器、固件、HCI 传输和 `rfkill` 状态，再分析扫描或连接。
- 配对、保存密钥、链路加密和 GATT 权限是不同检查点。
- `btmon` 观察主机与控制器的 HCI 交互，不能替代空口抓包。

适用范围：Linux 6.18 LTS；用户空间命令以系统安装的 BlueZ 为准。

## 分层

```text
应用 → Linux 用户空间蓝牙服务 / API → 内核蓝牙子系统
→ HCI 传输（如 UART、USB）→ 蓝牙控制器 → 无线链路
```

常见 Linux 系统使用 BlueZ；具体服务、版本和访问权限由发行版决定。HCI 是主机与控制器之间的接口，不是空口上的 GATT 数据格式。

## BLE 常见协议分工

| 层次 | 作用 |
| --- | --- |
| Controller / Link Layer | 负责射频、链路层及控制器侧流程 |
| HCI | 主机与控制器交换命令、事件和数据，承载于 USB、UART 等传输 |
| L2CAP | 提供上层协议需要的逻辑信道和数据适配 |
| ATT / GATT | 以属性组织服务、特征值、描述符和访问操作 |
| GAP / SMP | 分别涉及发现、连接等通用过程，以及安全管理相关过程 |

应用读写或订阅特征值发生在连接建立之后；通知是否送达还与对端是否启用通知、链路状态及应用处理有关。连接参数会影响功耗和响应间隔，但实际吞吐还受 PHY、控制器和应用数据路径影响。

## 连接与安全状态

扫描依赖控制器能力、广播间隔、扫描配置及对端状态。设备使用可解析私有地址等隐私机制时，地址会随时间变化；绑定和识别不能只依赖一次扫描看到的地址。

配对协商安全材料，bonding 通常涉及保存密钥以供后续使用；连接加密与身份认证强度由实际安全模式决定。GATT 的属性权限可能要求加密或认证，因此“已连接但读写失败”应检查错误码和访问要求，而不是直接重启控制器。

`btmon` 适合判断 HCI 命令、事件、连接与控制器响应；它看不到所有射频碰撞、链路层重传或对端内部状态。日志可能包含地址、应用载荷及安全相关信息，分享前按内容检查。

## 常见故障与下一步

| 现象 | 优先检查 |
| --- | --- |
| 没有适配器 | 总线设备、控制器供电、固件、内核驱动和 HCI 传输 |
| 适配器存在但不能扫描 | `rfkill`、控制器状态、服务权限、扫描参数和无线环境 |
| 扫描到设备但连接失败 | 地址类型、对端是否可连接、连接参数及 HCI 失败事件 |
| 连接成功但配对失败 | 双方安全能力、用户交互、密钥状态和配对事件 |
| 连接成功但 GATT 操作失败 | 服务发现、句柄、属性权限、加密 / 认证状态和 ATT 错误 |
| 订阅后没有通知 | 对端配置、连接状态、特征值通知能力与应用接收路径 |

定位时先用 `rfkill list bluetooth` 和 BlueZ 工具确认本机状态，再结合 `btmon` 捕获同一次测试的事件；需要分析无线链路时使用适合的空口工具。

| 过程 | 关注点 |
| --- | --- |
| 发现 | 广播内容、扫描状态、地址类型、信号与扫描过滤 |
| 建立连接 | 连接参数、控制器能力、射频环境与对端状态 |
| 配对 / bonding | 密钥协商与是否保存密钥；成功连接不等于已完成配对 |
| 加密 / 身份认证 | 按双方能力和安全策略协商；加密不自动证明应用层身份 |
| GATT | 通过服务和特征值进行读写、通知等操作；权限可能要求加密或认证 |

## 排查

1. 检查控制器是否被识别、固件是否加载、`rfkill` 是否阻止，以及 UART / USB 传输是否正常。
2. 用发行版提供的工具观察适配器状态和系统日志；可使用 `btmon` 同时记录 HCI 交互，注意抓取权限和敏感内容。
3. 区分扫描不到、连接失败、配对失败和 GATT 权限失败，不要用“蓝牙不通”概括所有层次。
4. BLE 地址可能具有隐私特性；不要把一次观察到的随机地址直接当成永久硬件身份。
