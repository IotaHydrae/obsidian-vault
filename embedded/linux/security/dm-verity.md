## 什么是 dm-verity

**dm-verity**（Device Mapper Verity）是 Linux 内核中一个非常硬核且优雅的只读块设备完整性保护机制。简单来说，它的核心任务是：**确保你的系统分区（比如 Android 的 system 分区或固态设备的固件）每一比特都没有被篡改过。**

### 1. 它是如何工作的？（哈希树机制）

dm-verity 并不像普通的校验工具那样在启动时扫描整个磁盘（那样太慢了），它利用了 **Merkle Tree（哈希树）** 结构进行按需验证。

- **分块处理：** 磁盘数据被分成固定大小的块（通常是 4KB）。
    
- **层层哈希：** 每个数据块都有一个哈希值，这些哈希值作为叶子节点，向上继续计算哈希，直到生成一个唯一的 **Root Hash（根哈希）**。
    
- **按需校验：** 当系统读取某个数据块时，它会实时计算该块的哈希，并一路向上与哈希树对比。如果任何一级校验失败，内核会直接拒绝读取，或者触发重启。

### 2. 为什么需要它？

在没有 dm-verity 的情况下，黑客如果获取了 root 权限，可以偷偷修改系统二进制文件（比如植入后门）。即便你有“安全启动”，一旦系统跑起来了，静态的文件就失去了保护。

**dm-verity 解决了两个痛点：**

1. **防篡改：** 哪怕只改动一个字节，Root Hash 就会完全对不上，系统立刻察觉。
    
2. **性能平衡：** 只有在读取数据时才校验，不读不校验，最大程度减少性能开销。

### 3. 典型应用场景

- **Android 系统：** 自 Android 4.4 以来，这是保证系统分区不被“刷机”或被病毒感染的核心技术。这也是为什么修改了系统分区后，手机可能无法启动或提示“系统已损坏”。
    
- **ChromeOS：** Google 极其依赖它来构建其极简且安全的架构。
    
- **固件保护：** 路由器、智能摄像头等嵌入式设备常用它来防止固件被恶意替换。
    

---

### 4. 局限性

- **只读：** 顾名思义，它只适用于不经常变动的数据分区。如果你想对频繁写入的 `/data` 分区做完整性保护，那得看 `dm-integrity` 或者文件系统级别的 `fs-verity`。
    
- **更新麻烦：** 每次 OTA 更新系统，都需要重新计算整棵哈希树并更新 Root Hash。


## 内核配置

内核配置打开 `CONFIG_DM_VERITY`，同时也可以考虑打开：

- **CONFIG_DM_VERITY_FEC:** 支持前向纠错（Forward Error Correction）。如果磁盘发生轻微损坏（如坏道），它可以尝试利用冗余数据修复，而不是直接让系统崩溃。
    
- **CONFIG_DM_VERITY_VERIFY_ROOTHASH_SIG:** 支持对 Root Hash 进行签名验证。这能防止攻击者伪造整个哈希树。
