# 启动 IO 争抢的采样与归因

> 总设备 IO、进程累计 IO 与服务关键路径回答不同问题；相关性需要干预对照才能支持原因判断。

## TL;DR

- diskstats 提供设备总账，按 512 字节扇区换算；整盘与分区不能重复累计。
- maps 是虚拟映射，不能当实读字节数；父子进程累计 IO 也可能重复。
- 优先按实际 cgroup 控制器做服务统计，再结合 CPU、缺页与等待分析。
- 稳态清页缓存不等于完整开机环境，预热是否有效必须比较同一用户终点。

## 探针选择

| 观测 | 可用入口 | 不能单独证明 |
| --- | --- | --- |
| 启动阶段 | journal、systemd critical-chain | 进程内 IO 来源 |
| 设备窗口 | /proc/diskstats、iostat | 某应用独占多少字节 |
| 服务组 | 可用 cgroup io.stat/blkio | 所有缓存命中与端到端时延 |
| 进程活动 | /proc/PID/io、iotop | 父子累加后的精确归因 |
| 函数/系统调用 | perf、strace、block trace | 无探针时的原始性能 |

检查当前 cgroup 是 v1、v2 还是混合，不按固定路径推测控制器不存在。
字段单位和累计时间窗需按当前内核核对。

## 两种常见误算

mmap 通常按需取页；一个大映射不表示全部文件已从介质读取，多个进程还可能共享页缓存。
把 `/proc/PID/maps` 中的文件大小相加会混入未访问页与重复库。

进程退出并被回收后，部分 IO 统计会累计到父进程。若分别取子进程与之后父进程最大值再相加，
可能重复计数；窗口前的累计值也不能全算进当前窗口。核对目标内核的 proc/exit 实现与采样方式。
设备总量可交叉检查总账，不能把差额直接分配给某应用。

## 有效 A/B

固定起止事件和输入，记录设备队列、CPU、major faults 与并发服务。
只改变一个候选工作的位置或行为，观察同一终点是否提前，功能和总工作量是否保持。
服务延后导致目标更早只说明此安排有效，根因仍需结合等待与 IO 证据。

`drop_caches` 会改变系统状态与其他程序行为，仅在已授权实验中使用。
开机探针应异步采样，不能把等待完整采样窗口的 oneshot 放进被测关键路径。
测完撤回探针、trace 和临时单元，保留日志与采样条件。
