函数式宏（Function-like Macros）是过程宏的一种。它们看起来和我们之前学的 `macro_rules!` 非常像，都是通过 `名字!(...)` 的形式调用，但其内部实现完全不同。

`macro_rules!` 使用的是简单的模式匹配，而函数式宏运行的是真正的 **Rust 代码**。这使得它们能够执行复杂的逻辑，比如解析一种全新的编程语言或根据外部文件生成代码。

### 函数式宏的结构 🏗️

函数式宏的定义如下：

```rust
use proc_macro::TokenStream;

#[proc_macro]
pub fn my_macro(input: TokenStream) -> TokenStream {
    // 这里的 input 是括号内的所有内容
    // 我们可以对它进行任意的逻辑处理
    // 最后返回生成的 Rust 代码
    input
}
```

### 为什么需要它？ 🤔

相比于声明式宏，函数式宏有两个核心优势：

1. **无限的逻辑能力**：你可以使用循环、条件判断、甚至是文件 I/O。
    
2. **更强的解析力**：它可以处理 `macro_rules!` 无法表达的复杂语法。

### 举个例子：SQL 检查器 🔍

想象一下，如果你想写一个宏，在**编译阶段**检查你的 SQL 语句语法是否正确：

```rust
let query = sql!("SELECT * FROM users WHERE id = 1");
```

如果是用 `macro_rules!`，它只能检查括号里的标记是否符合某种模式。但如果是函数式宏，它拿到字符串后，可以调用一个真正的 SQL 解析库，如果发现 SQL 写错了，直接在编译时报错！

### 动手思考 💡

假设我们要写一个简单的函数式宏 `make_public!`。它的作用是：接收一段 `struct` 定义，然后强行给这个结构体加上 `pub` 关键字。

输入：`struct User { name: String }` 输出：`pub struct User { name: String }`

如果要实现这个功能，你觉得在宏的内部逻辑中，我们应该如何处理拿到的 `TokenStream`？

1. 把它当成一个纯字符串，然后在开头拼接 `"pub "`。
    
2. 使用 `syn` 将其解析为语法树（AST），修改可见性属性，然后再转回代码。
    
3. 直接原封不动地返回，因为 Rust 宏会自动处理可见性。
    

你倾向于选哪种方式？

> 2

选择第 2 种方案（使用 `syn` 解析为语法树）是处理过程宏的最佳实践！🧬

虽然直接拼接字符串（方案 1）看起来简单，但它极其脆弱。如果输入的代码带有注释、属性标签或者复杂的泛型，字符串拼接很容易破坏语法结构。而通过 `syn` 解析，我们可以精确地定位到结构体的“可见性”字段并进行修改。

### 函数式宏的工作原理 🛠️

在函数式宏中，你会得到一个 `TokenStream`，它代表了 `my_macro!(...)` 括号里的所有内容。

为了实现 `make_public!`，我们需要：

1. 使用 `syn` 将 `TokenStream` 解析为 `ItemStruct`（结构体项）。
    
2. 修改该结构体的 `vis`（Visibility，可见性）字段。
    
3. 使用 `quote` 将修改后的语法树重新转回代码。
    

**宏定义代码大致如下：**

```rust
#[proc_macro]
pub fn make_public(input: TokenStream) -> TokenStream {
    // 1. 解析成结构体语法树
    let mut item_struct = parse_macro_input!(input as ItemStruct);

    // 2. 将可见性修改为 pub
    // syn::Visibility::Public 会生成 'pub' 关键字
    item_struct.vis = syn::parse_quote!(pub);

    // 3. 重新变成代码
    let expanded = quote! {
        #item_struct
    };

    expanded.into()
}
```

### 宏的边界：什么时候该停下来？ 🛑

我们已经聊完了 Rust 宏的三大门派。虽然宏非常强大，但在 Rust 社区中有一条不成文的准则：**能用函数或泛型解决的问题，就不要用宏。**

这是因为宏也带有一些代价：

- **编译时间**：复杂的宏会显著增加编译时间 ⏱️。
    
- **可读性**：宏生成的代码在编辑器里很难直接跳转调试 🧩。
    
- **错误提示**：宏内部的逻辑错误有时会导致编译器给出令人困惑的报错信息。

你觉得这属于我们聊过的哪一种宏？

1. 派生宏 (Derive Macro)
    
2. 属性宏 (Attribute Macro)
    
3. 函数式宏 (Function-like Macro)
    

你想选哪一个作为我们这次学习的收官答案？

> 2

你观察得很敏锐！没错，这就是**属性宏 (Attribute Macro)** 🏷️。

属性宏是实现“声明式编程”最强大的手段之一。像 `#[get("/index")]` 这样的标签，实际上在编译阶段告诉 Rust：“请把下面这个函数交给路由宏处理，并标记它处理来自 `/index` 的 GET 请求。”

### 属性宏的魔力 🪄

属性宏之所以能实现这种功能，是因为它能**看到并修改**被它标记的代码。相比之下：

- **派生宏** 🧬 只能在结构体旁边“加点东西”（比如实现 Trait），不能改动结构体本身。
    
- **属性宏** 🏷️ 则是“接管”了它标记的代码块。它能把一个普通的函数包装成异步函数，或者自动注入数据库连接代码。
