# Linux GPU 固件版本提示：如何判断是否需要处理

> 区分建议版本、加载结果和实际 GPU 故障；版本提示本身既不能证明卡顿根因，也不能证明固件加载失败。

## TL;DR

- 从同一次启动的完整日志判断固件是否加载、功能是否启用、是否发生 hang/reset。
- 磁盘上的文件、initramfs 和当前已加载固件可能处于不同状态。
- 软件源刷新失败时，包管理器的候选版本可能只是旧索引结果。

## 排查顺序

```bash
uname -r
journalctl -k -b --no-pager | grep -Ei 'i915|xe|GuC|HuC|firmware|hang|reset'
```

结合目标驱动确认“recommended”和实际要求的含义；存在建议版本不同但仍可加载的情况，不能推广为所有固件版本都可互换。继续查看加载成功、提交功能、超时和重置记录，并复现实际业务故障。

在 Debian / Ubuntu 中可用 `apt-cache policy <实际固件包名>` 查看安装及候选版本，另行确认索引更新是否成功。包名按发行版核对，不固定假设每台机器都有同一个 Intel graphics 包。

## 更新与验收

优先匹配发行版支持的内核及固件包，检查文件归属和启动镜像更新钩子。单独重启不会凭空生成新固件；文件已更新也不表示当前驱动已使用它。

需要重新加载驱动或重启才能使用新固件时，应按运行环境安排，保留恢复路径。更新后对比加载版本、同一业务、错误日志与可用功能，不能只以提示文字消失验收。

参考：[Linux i915 文档](https://docs.kernel.org/gpu/i915.html)。
