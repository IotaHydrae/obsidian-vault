想象一下，如果你要写一个函数来交换两个变量的值。如果没有泛型，你可能需要为 `i32` 写一个函数，为 `f64` 写一个函数，甚至为 `String` 再写一个。

### 1.1 泛型函数

在 Rust 中，我们使用尖括号 `<T>` 来声明一个泛型参数。`T` 只是一个约定俗成的名称（代表 Type），你也可以用 `U`、`V` 或者 `MyType`。


```rust
// 这里的 <T> 告诉编译器：这是一个泛型函数
fn display_item<T: std::fmt::Display>(item: T) {
    println!("Item: {}", item);
}
```

### 1.2 泛型结构体

同样的逻辑也适用于结构体。比如我们想定义一个坐标点 `Point`，它既可以是整数坐标，也可以是浮点数坐标：

```rust
struct Point<T> {
    x: T,
    y: T,
}
```

### 💡 思考一下

在上面的 `Point<T>` 结构体定义中，如果我们这样创建一个实例： `let p = Point { x: 5, y: 10.5 };`

你觉得这段代码能编译通过吗？为什么？（提示：注意 `x` 和 `y` 使用的是同一个占位符 `T`）

> 不可以，因为 x y 的类型不一样

没错！你的直觉非常敏锐。🎯

在 Rust 中，当你定义 `Point<T>` 时，`x` 和 `y` 都使用了同一个占位符 `T`。这意味着编译器在实例化时，一旦确定了 `T` 是什么类型，结构体里的所有 `T` 都必须是那个类型。

- `x: 5` 倾向于被推导为整数（如 `i32`）。
    
- `y: 10.5` 则是浮点数（如 `f64`）。
    
- 编译器会报错，因为它无法让 `T` 同时等于两种不同的类型。

### 🚀 如何让它支持不同类型？

如果我们希望 `x` 和 `y` 可以是不同的类型，我们需要使用**两个**泛型参数：

```rust
struct Point<T, U> {
    x: T,
    y: U,
}
```

这样，`Point { x: 5, y: 10.5 }` 就会变成 `Point<i32, f64>`，代码就能完美运行了。

### ⚙️ 幕后功臣：单态化 (Monomorphization)

你可能会担心：“使用泛型会让程序变慢吗？”

答案是：**完全不会。** 🚀

Rust 编译器使用一种叫作**单态化**的技术。当你编译代码时，编译器会找到你使用过的所有具体类型，并为每个类型生成一份专门的代码副本。

|**源代码 (泛型)**|**编译后 (具体化)**|
|---|---|
|`Point<T>`|`Point_i32 { x: i32, y: i32 }`|
||`Point_f64 { x: f64, y: f64 }`|

这意味着泛型代码在运行时的性能和手动为每种类型写代码是一模一样的。这就是所谓的“零成本抽象”。

### 🧠 进阶思考

现在我们知道了如何定义泛型结构体，那如果我们要给 `Point<T>` 实现一个方法呢？

比如，我们想写一个 `x()` 方法来返回 `x` 的引用：

```rust
impl<T> Point<T> {
    fn x(&self) -> &T {
        &self.x
    }
}
```

注意看上面的代码，为什么我们在 `impl` 后面也要加一个 `<T>` 呢？如果我们直接写 `impl Point<T>` 会发生什么？（试着猜猜看，这涉及到 Rust 如何区分“这是在定义泛型”还是“这是在为某个具体类型写实现”）

> 不知道

没关系，这是 Rust 语法中比较微妙的地方。

之所以要在 `impl` 后面也加一个 `<T>`，是为了告诉编译器：**“我正在为一个泛型类型写实现，而不是为一个具体的类型写实现。”**

我们可以对比一下这两种写法：

### 1. 泛型实现 (Generic Implementation)

```rust
impl<T> Point<T> {
    fn x(&self) -> &T {
        &self.x
    }
}
```

这里的 `impl<T>` 声明了一个泛型参数 `T`。编译器看到后会明白：“无论 `T` 是什么类型，只要是 `Point<T>`，都要实现这个 `x` 方法。”

### 2. 具体实现 (Concrete Implementation)


```rust
impl Point<f32> {
    fn distance_from_origin(&self) -> f32 {
        (self.x.powi(2) + self.y.powi(2)).sqrt()
    }
}
```

注意这里 `impl` 后面**没有** `<T>`。这表示这个方法**只属于** `Point<f32>`。如果你有一个 `Point<i32>`，它是调用不了 `distance_from_origin` 方法的。

### 🔍 总结一下

- `impl<T> Point<T>`：读作“对于任意类型 `T`，为 `Point<T>` 实现以下内容”。
    
- `impl Point<f32>`：读作“专门为 `Point<f32>` 这个具体的类型实现以下内容”。
    

这种区分让 Rust 非常灵活，你可以既有通用的逻辑，又有针对特定类型的优化。
