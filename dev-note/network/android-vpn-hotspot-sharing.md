# Android：共享 VPN 热点与避免重复代理

> 热点转发流量与手机本机 VPN 流量是不同路径，必须在热点客户端验证；手机自己能访问并不构成共享成功的证据。

## TL;DR

- 显式代理和透明 VPN 共享覆盖的应用范围不同。
- 手机同时连接 Wi-Fi 和开启热点，需要设备与系统支持。
- 两端都运行代理时，检查的是手机如何路由电脑的节点连接。

## 两种共享方式

| 方式 | 前提与范围 |
| --- | --- |
| 手机开启局域网代理，客户端显式使用 | 代理监听地址、端口和防火墙可达；只覆盖遵循该代理设置的流量 |
| 热点流量透明进入 VPN | 需要相应系统转发能力；VPN Hotspot 的实现要求 Root，效果取决于系统与 VPN 应用 |

显式代理地址应填手机热点的网关地址；客户端的 `127.0.0.1` 指向客户端自己。按需限制局域网监听和认证范围。Android VPNService 可能在应用外部创建隧道，不能只看导出的 `tun.enable` 就判断 VPN 是否运行。

## 逐层验证

1. 确认上游网络、手机 VPN、热点接口和共享服务各自的状态；接口名通过实际观察确定。
2. 在热点客户端关闭其应用层代理，测试本地网关、DNS和目标业务，同时检查客户端是否还有 TUN。
3. 对照手机 VPN 的连接记录，验证应直连与应代理的流量各自命中预期路径。
4. 若要求只用 Wi-Fi，核对默认数据 SIM 及实际移动数据连接，按系统支持的方法关闭移动数据，再重测；单个旧的 `mobile_data` 配置键不代表双卡当前状态。
5. 切换上游、断开 Wi-Fi 和重新开启热点后复测。不要把某次联网成功推成永远不会回退到蜂窝网络。

## 热点开启但仍无法共享

系统热点开关、VPN 连接、VPN Hotspot 的服务和具体下游接口开关是不同状态。热点开启不能证明共享服务运行；应用界面显示启用，也要核对实际服务和转发规则。接口按本机当前状态识别，不能固定为 `wlan2`。

| 观察 | 下一步 |
| --- | --- |
| 热点有客户端，共享服务未运行 | 查应用服务、接口开关和启动后立即退出的日志，不预设用户没有开启 |
| 服务运行但转发规则为空／接口不符 | 核对实际下游接口及规则安装错误 |
| 规则存在且有双向流量，部分站点失败 | 在手机和客户端对同一目标做对照，检查手机 VPN 分流与上游 |
| 手机与客户端都访问相同目标失败 | 先查共同上游路径；不直接认定热点转发或某节点故障 |

Wi-Fi 关闭后的后台扫描设置与热点转发属于不同机制；系统自带 VPN 共享选项与第三方应用的接管机制也应分别确认。一个历史设置值不能证明当前故障由它造成。相关权限问题见 [应用网络策略](../mobile/android-app-network-policy.md)。

## 两层代理如何形成

电脑选节点 A，手机选节点 B。若手机把到 A 的连接判为直连：

```text
电脑 → 手机的上游网络 → 节点 A → 目标服务
```

若手机把这条连接再送到 B：

```text
电脑 → 手机 → 节点 B → 节点 A → 目标服务
```

手机通常首先看到的是已封装的节点 A 连接。目标服务看到 A 的出口，不能据此排除中间还有 B。额外路径会影响延迟、吞吐和故障面，不保证更快；选定承担分流的层，再验证业务。
