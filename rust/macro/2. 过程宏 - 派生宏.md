既然我们决定从**派生宏 (Derive Macros)** 开始，那我们先来看看它最神奇的地方：它能让你在不手写任何逻辑的情况下，赋予一个结构体某种“能力”。

在 Rust 中，派生宏是通过 `proc_macro_derive` 属性定义的。它的输入是你的结构体或枚举的定义，输出则是为该类型自动生成的 `impl` 代码块。

### 它是如何工作的？⚙️

当你写下 `#[derive(Hello)]` 时，编译器会把整个结构体的源代码作为一串**标记流 (TokenStream)** 传给宏函数。宏函数就像一个“代码编译器”，它会分析这些标记，然后吐出新的代码。

为了处理这些标记流，我们通常需要两件利器：

1. **syn**：一个将源代码标记解析成易于操作的“语法树”的库（比如能让你直接拿到结构体的名字、字段名）。
    
2. **quote**：一个将 Rust 代码转换回标记流的库，让你能像写普通代码一样写宏的输出。

### 核心流程 🛠️

一个典型的派生宏函数长这样：

```rust
#[proc_macro_derive(Hello)]
pub fn hello_derive(input: TokenStream) -> TokenStream {
    // 1. 解析输入：把 TokenStream 变成一个结构体对象
    let ast = syn::parse(input).unwrap();

    // 2. 构建输出：生成 impl Hello for ... 代码
    impl_hello_macro(&ast)
}
```

### 设想一下 💡

假设我们有一个结构体：

```rust
struct User {
    name: String,
}
```

如果我们想为它自动实现一个 `hello()` 方法，打印出 "Hello, I am User"。

在这个过程中，宏需要从输入的代码中提取出哪个关键信息，才能生成 `impl User { ... }` 这一行？你会选择提取：

1. 字段的类型（如 `String`）
    
2. 结构体的名称（如 `User`）
    
3. 字段的名称（如 `name`）

> 2

完全正确！🎯 结构体的**名称**（如 `User`）是生成 `impl` 块时最关键的信息。

在过程宏中，我们使用 `syn` 库将输入的代码解析为一种树状结构（AST）。对于结构体，这个结构被称为 `ItemStruct`。

### 提取名称的逻辑 🔍

如果你在宏代码中解析了输入：

```rust
let input = parse_macro_input!(input as DeriveInput);
let name = &input.ident; // 这里就拿到了结构体的名字，比如 User
```

代码生成示例 ✨

```rust
let expanded = quote! {
    impl #name {
        pub fn hello(&self) {
            println!("Hello, I am {}", stringify!(#name));
        }
    }
};
```

这段代码会被转换回 `TokenStream` 并交给编译器。最终，编译器看到的就像是你亲手写了 `impl User { ... }` 一样。
