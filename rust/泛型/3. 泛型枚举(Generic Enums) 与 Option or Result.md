在很多语言中，处理“空值”或“错误”往往依赖于 `null` 或 `Exception`。但 Rust 不一样，它利用泛型定义了两个极其重要的枚举，彻底改变了这种游戏规则。

### 3.1 `Option<T>`：再见，Null！

在 Rust 中没有 `null`。相反，我们有一个泛型枚举：

```rust
enum Option<T> {
    Some(T), // 包含一个 T 类型的值
    None,    // 什么都没有
}
```

**为什么这很天才？** 因为如果你有一个 `Option<String>`，编译器会**强制**你处理 `None` 的情况，否则代码根本编译不过。

```rust
let name = Some(String::from("Gemini"));
let unknown: Option<String> = None;

// 你不能直接把 unknown 当字符串用，必须通过模式匹配“拆箱”
```

### 3.2 `Result<T, E>`：优雅的错误处理

另一个重量级选手是 `Result`。它有两个泛型参数：一个是**成功时的类型 `T`**，另一个是**失败时的类型 `E`**。

```rust
enum Result<T, E> {
    Ok(T),  // 操作成功，返回结果
    Err(E), // 操作失败，返回错误原因
}
```

当你尝试打开一个文件或连接网络时，Rust 不会抛出异常，而是返回这个枚举。

```rust
fn divide(numerator: f64, denominator: f64) -> Result<f64, String> {
    if denominator == 0.0 {
        Err(String::from("不能除以零！"))
    } else {
        Ok(numerator / denominator)
    }
}
```

### 3.3 泛型参数的灵活性

注意看 `Result<T, E>`，它证明了**泛型可以有多个，且互不干扰**。

- `T` 可以是一个 `i32`。
    
- `E` 可以是一个 `String` 或者一个自定义的结构体。

### 📝 总结：泛型的三个境界

1. **初级**：用 `<T>` 减少重复代码（结构体、函数）。
    
2. **中级**：用 `Trait Bounds` 给 `T` 立规矩，让它具备能力（如 `Display`）。
    
3. **高级**：利用泛型构建强大的类型系统（如 `Option` 和 `Result`），在编译阶段就消灭运行时的隐患。
