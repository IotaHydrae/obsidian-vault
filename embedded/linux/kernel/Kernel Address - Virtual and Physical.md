### 1. 内核变量的地址是虚拟地址还是物理地址？

**结论：是虚拟地址。**

在几乎所有现代通用的 Linux 系统中（即带有 MMU 内存管理单元的 CPU，如 x86, ARM, RISC-V 等），内核代码中访问的所有变量地址、函数地址、以及通过 kmalloc() 或 vmalloc() 分配的指针地址，全部都是虚拟地址（更准确地说是内核空间的虚拟地址，有时也称为逻辑地址）。

- MMU 的作用：CPU 在执行指令访问内存时，地址线发出的请求会被 MMU 拦截并根据页表（Page Tables）转换成物理地址。
- 例外：只有在极少数嵌入式系统或特定模式下（如 uClinux 或系统刚启动尚未开启 MMU 之前），内核才会直接在物理地址上运行。

### 3. 如果在驱动中直接访问物理地址会怎么样？

如果你尝试像操作普通指针一样直接解引用一个物理地址（例如 `*(unsigned int *)phys_addr = 0x123;`)，通常会发生以下情况：

1. **访问错误（Oops/Panic）**：  
    CPU 会把这个“物理地址”**当作“虚拟地址”**传给 MMU。由于物理地址通常落在 0 开始的低位空间，而内核代码运行在高端虚拟地址（如 0xC0000000 以上或特定的内核区域），这个物理地址对应的虚拟地址位通常是没有映射的（Invalid Page Table Entry）。结果是触发一个 **Kernel Oops**（类似用户态的段错误 Segfault），导致驱动崩溃甚至内核挂起。
    
2. **数据损坏（Silent Corruption）**：  
    极少数情况下，如果这个物理地址刚好对应了一个已经存在的虚拟地址映射，你可能会修改掉内核其他模块的数据，造成难以排查的随机崩溃。
    

#### 正确做法：物理地址必须“映射”后访问

在驱动程序中，如果你有一个硬件寄存器的物理地址（比如从设备树读取的），必须先通过 **ioremap()** 函数将其映射到内核虚拟地址空间，然后才能访问：

```c
// 1. 获取映射后的内核虚拟地址
void __iomem *v_addr = ioremap(PHYS_ADDR, SIZE);

// 2. 使用专门的 IO 访问函数（不要直接解引用）
unsigned int val = ioread32(v_addr);
iowrite32(0x1234, v_addr);

// 3. 释放映射
iounmap(v_addr);
```
