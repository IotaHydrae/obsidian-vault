# CM4 Celluloid：硬件解码与显示丢帧

> CM4 视频流畅度需分别检查硬件解码和显示丢帧，开启硬解仍可能丢帧。

## TL;DR

- Celluloid 默认 `--hwdec=auto --profile=fast`，保留已有用户偏好的优先级。
- 当前 H.264 实测为 v4l2m2m-copy；720p30 两次稳定窗口无新增丢帧，1080p30 仍有残余。
- 记录解码器与输出丢帧增量；软件计数不能代替实体音画同步观察。

## 方法：先识别实际解码器，再比较稳定窗口增量

用已知编码、分辨率、帧率和时长的媒体，记录应用版本、实际解码设备及 IPC 属性。
全屏稳定后，在同样长度窗口分别取输出和解码丢帧增量；保留反向原配置对照。
另外检查已知画面与暂停/继续状态，物理音画同步用独立观察，不从静音测试的内部时钟推出。

## 默认配置与取舍

mpv 0.37 的 fast profile 使用双线性缩放，关闭抖动、线性/高质量缩放及部分 HDR
峰值计算，牺牲部分处理质量以降低显示成本。仅改变 GTK 缩放或渲染器未消除该问题，
不应降低用户已确认合适的全局 150% 缩放来掩盖它。

Ubuntu 桌面通过标准 GSettings distribution override 设置 Celluloid 的
`mpv-options='--hwdec=auto --profile=fast'`，安装后显式编译 schemas。
已有用户的显式配置优先；不在 desktop 启动参数中强行覆盖用户选择。
主机测试使用真实 GLib keyfile backend，验证先存的用户值在安装 override 后仍保留，
reset 后才使用工程默认。无桌面配置不安装该 override。

实机安装并编译 override 后，以不传 hwdec/profile 参数的新 Celluloid 实例复验：
实际选中 `v4l2m2m-copy` 与 bilinear/no-dither 配置，12 次稳定采样中没有新增输出丢帧。
另外将 idle 超时临时改为 3 秒：播放推进时输出保持开启，关闭测试播放器后自动熄屏，
注入按键后自动恢复。测试结束逐字节恢复原配置，生产超时仍为 600 秒、临时锁屏仍禁用。
这验证了当前播放器与空闲策略的协作，不证明所有浏览器或音乐应用也有相同行为。

## 分开验证解码与输出

2026-10-25，同一 CM4 SD 启动 `00000000-0000-4000-8000-000000000035`，
Celluloid 0.26、libmpv 0.37.0、FFmpeg 6.1.1、GTK 4.14.5、系统 Mesa 25.2.8。
桌面保持 transform 270、scale 1.5、背光 4/9。应用继续使用系统图形库。

主机生成已知 H.264 High/yuv420p、30 fps、28 秒视频与 AAC 音轨；
720p 约 4 Mbps、1080p 约 8 Mbps。通过实际 Celluloid 的 mpv IPC、日志、
设备文件和全屏截图交叉检查：

- 原始配置走软件解码。
- `hwdec=auto` 实际打开 `/dev/video10` 并报告 `v4l2m2m-copy`，证明 H.264 解码路径接通。
- 硬解时解码器丢帧为 0，输出丢帧仍增长，说明不能仅按硬解状态宣布播放流畅。
- HEVC 请求式节点接受 `S265`，发行版 FFmpeg 没有对应 `hevc_v4l2request`；
  设备节点存在不能证明 HEVC 硬解可用。

每轮全屏稳定 2 秒后，取 16 次约一秒间隔采样。下表是稳定区间的
`frame-drop-count` 增量，排除启动和全屏切换；均不是自定的通过/失败阈值。

| 配置 | 采样跨度 | 输出新增丢帧 | 解码器新增丢帧 |
| --- | ---: | ---: | ---: |
| 原始 720p30 | 15.48 s | 214 | 0 |
| 仅自动硬解 720p30 | 15.52 s | 230 | 0 |
| 自动硬解与 fast，720p30 | 15.54 s | 0 | 0 |
| 重复 fast，720p30 | 15.52 s | 0 | 0 |
| 随后反向原始对照，720p30 | 15.49 s | 215 | 0 |
| 仅自动硬解 1080p30 | 15.84 s | 319 | 0 |
| 自动硬解与 fast，1080p30 | 15.69 s | 22 | 0 |

全屏截图包含已知测试图，暂停后位置保持不变。重复轮次内部 AV 时钟的最大观察偏差
为 0.356 ms；测试播放器静音，这不能证明物理扬声器与屏幕同步。

## 功耗与跨平台边界

短时电池侧整机功率由实际 `voltage_now × abs(current_now)` 得到，720p fast 两轮
中位数约 3.73/3.61 W，1080p fast 约 4.21 W。它们来自顺序采样且未经仪器校准，
不能单独归因于解码器，也不能外推续航。各轮采样温度约 37.0–40.4 °C，保护标志为 0。

移植到 CM5、Rockchip 或其他核心板时，分别核对压缩格式、内核设备接口、用户态解码器、
应用选中的解码路径以及最终显示输出；不要复制设备编号或把 V3D 渲染等同于视频解码。
高码率、其他编码格式、在线视频及物理音画同步仍需单独验证。

完整非发布测量位于 `~/.cache/uconsole-desktop-20261025/video/`，包含固定媒体的
ffprobe 信息、摘要、命令、逐样本属性、日志与截图。镜像构建输入与实机增量部署
分别记录于[开发状态](../../project/status.md)。
