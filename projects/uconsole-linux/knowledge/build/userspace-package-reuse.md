# 用户态预编译包复用与板级适配边界

> 用户态 deb 按架构、发行版 ABI 与固定输入复用；板级驱动能力单独验证。

## TL;DR

- 固定版本镜像直接安装校验通过的 deb 与回执，无需每次在 uConsole 上编译。
- 新克隆先执行 `git lfs pull`；非空缓存仍须验证来源、哈希和构建选项。
- CM4/CM5 不应进入通用用户态包身份；GPU、内核、DT 和固件按平台分别适配。

适用于本工程 Ubuntu 24.04 ARM64 固定配方；CM4 已验证，其他核心板需独立验证。

## 复用方法

1. 新克隆补齐 Git LFS 对象，保持 `.deb` 与 JSON 回执配对；只获得指针文件时先完成下载。
2. 选定 rootfs/桌面后，由共用包入口校验 ABI、固定输入、配方与产物，空缓存才导入跟踪包。
3. 非空缓存校验失败时先保留现场并查清输入变化，不用预编译包覆盖它，也不手改回执放行。
4. 更换核心板时先核对下面的用户态身份，再分别验证 GPU、内核、固件与启动介质。

## 为什么用户态包按 ABI 识别

通用应用包按目标架构和用户态环境识别，不能把 CM4/CM5 名称当作缓存身份。
核对以下条件后，镜像准备复用已有 `.deb` 与校验回执，不应每次构建镜像重新编译：

| 条件 | 应记录或核对的内容 |
| --- | --- |
| 目标 ABI | `arm64` / AArch64、Ubuntu 24.04 ABI、实际运行依赖及其兼容版本 |
| 源码身份 | 固定归档摘要、补丁及顺序、配方、构建器和校验器摘要 |
| 编译环境 | 工具链目标与版本、编译选项、Meson 实际生效选项、私有依赖固定版本 |
| 产物身份 | 包名/版本/架构、`.deb` SHA-256、构建回执及安装时校验 |

现有 Noctalia 配方要求原生 AArch64 Ubuntu 24.04 与 GCC 14；构建机可以是符合条件的
ARM64 机器，不必是 uConsole。`native_optimizations=false`，私有前缀隔离桌面依赖，
没有为 CM4 的 CPU 生成专属指令。符合 ABI 与依赖条件时，同一包可能用于 CM4、CM5
或 Rockchip ARM64 系统；这不是跨所有 ARM64 设备的兼容保证。
交叉编译属于后续能力，当前原生构建器未实现；原生路径不要求容器。

仅有“同为 Ubuntu 24.04”不足以证明依赖一致。发行版仓库会更新；当前回执记录构建时
解析到的运行库版本，包的 `Depends` 使用 `>=` 下限，既不是完整仓库快照，也不是
全部依赖的精确锁定。现有缓存校验核对固定输入、项目代码身份、包摘要、目标与 ELF
信息，不承诺未来仓库状态可逐字节重建。遇到 ABI/依赖变化，应重新核对和验证；需要
精确重建时还需保存相应工具链、依赖包或仓库快照。

## 包传输与缓存契约

固定包存放在 `prebuilt/ubuntu-noble/arm64/`。`.deb` 由 Git LFS 保存实际字节，
同名 `.json` 回执由普通 Git 保存；按用户态和架构分类，CM4、CM5 不另存一份。
LFS 负责传输，原有配方、构建器、校验器身份和包 SHA-256 仍负责拒绝过期或损坏输入。
现有 Git 历史不迁移，规则仅匹配该目录的 `.deb`。

新电脑先通过发行版安装 `git-lfs`，执行 `git lfs install`，再使用
`git clone --recurse-submodules`。正常检出会自动下载 LFS 对象；已有副本或设置过
`GIT_LFS_SKIP_SMUDGE` 的副本执行 `git lfs pull`。只得到 LFS 指针文件时，镜像工具
会报缺少环境并提示该命令，不会隐式联网或临时编译。远端对象发布与下载是否已验证，
以[开发状态](../../project/status.md)为准。

镜像准备、配置可用性检查和桌面镜像检查共用输入入口。忽略的
`image/work/wayland-stack/packages/` 或 `image/work/noctalia/packages/` 不存在或为空时，
入口从跟踪的包与回执原子填充该目录，再运行原有校验器。任何非空原生缓存优先；
即使只剩一个文件或回执过期，也直接报错，不用预编译包覆盖构建现场。
要重新选择跟踪的包，先将对应缓存目录移走保留，再重试。

更新固定包时，应保留原生构建生成的包与回执配对，在跟踪目录更新两者并重新校验；
不要手改回执摘要来接受旧产物。源码构建入口继续保留，可在独立 Ubuntu 24.04 ARM64
机器上运行；Noctalia 需要 GCC 14，当前没有 x86 交叉编译入口。

## 板级职责单独适配

| 用户态包可复用的部分 | 由板型/后端适配并实机验证的部分 |
| --- | --- |
| 通用应用代码、桌面配置机制、兼容 ABI 的私有库 | 内核、设备树、启动链与固件 |
| 不依赖特定 GPU 的渲染算法 | DRM/KMS、Mesa/GLES 驱动及各 GPU 的输出与性能 |
| 通用会话、权限和包安装流程 | 供电/稳压器、复位、屏幕、背光、输入及音频硬件 |

CM 接口或引脚兼容不等于供电时序、启动协议和软件兼容。Raspberry Pi 固件与设备树
不能直接视为 Rockchip 的启动后端；新的模块须按工程的独立板型和内核/启动后端接入。
桌面包与板级适配分开后，修一个应用无需重复构建内核、导出整镜像或刷写 SD 卡。

## CM5 只读核对证据（2026-10-21）

CM5 迁移应分别核对用户态、内核与启动介质；桌面包满足条件时直接复用。
以下为 2026-10-21 的只读检查结果及后续验证条件。

- **用户态 ABI：** 当前 Noctalia `5.3.0+uconsole1` 包要求 `libc6 >= 2.39` 和 Noble
  的 t64 依赖；Wayland 栈 `0.20.2+waybar0.15.0-1` 要求 `libc6 >= 2.38`。
  已记录的 CM5 社区系统为 Debian 12，不能直接安装这两个 Noble 包；应准备独立的
  Ubuntu 用户态，不通过替换原系统的 libc 来满足依赖。依据为两个 `.deb` 的
  `control/Depends` 与[参考系统记录](../../project/status.md#existing-device-observations)。
- **内核页大小：** 从两包的 `data.tar` 读取全部 40 个 ELF，80 个 `PT_LOAD` 段的
  `p_align` 均为 65536，且 `p_offset` 与 `p_vaddr` 在 16 KiB 下同余。这支持在 CM5
  16 KiB 页内核上继续验证，但未覆盖发行版依赖库，也不能证明实际加载、内存映射、
  GPU 和会话功能正常；必须在目标内核运行后确认。
- **独立内核输入：** CM4 本地配置中的 `kernel_report` 固定到 CM4 报告，不能仅改
  `BOARD` 后沿用。CM5 应独立选择报告及其 SHA-256，并保留自身启动配置。此次
  `make -f Makefile.agent kernel-artifact BOARD=uconsole-cm5` 先因面板补丁 `0001`
  摘要漂移而拒绝旧产物；`0002`、`0003` 摘要仍匹配，但配置片段摘要也已漂移。
  显式历史校验接受现存的 `6.18.57-v8-16k-uconsole` 包、配置和 Image。
  需要保留基线时可使用这一明确路径，
  不应放宽严格校验或把旧包称为当前源码构建；契约见历史内核选择（工程源码：`image/ubuntu-base/README.md`）。
- **实际显示输出：** 桌面默认匹配 DSI-1/DSI-2；此前 CM5 主机重绑出现过 DSI-3。
  每次试验应检查当前 DRM 连接器和背光设备，再设置旋转、缩放和亮度，不能把编号当作
  板型常量。见[CM5 面板对照](../display/cm5-panel-module-comparison.md)。
- **存储与恢复：** 这块 CM5 为 eMMC 型号，底板 microSD 插槽不可用，详见
  [CM5 存储接线](../storage/cm5-storage.md)。外部 USB 启动须先确认启动顺序与恢复
  路径；原 eMMC 部署恢复流程尚未验证。构建、检查或准备桌面包不能隐含授权覆盖原系统。

## 小步优化与验证循环

本次 Noctalia 菜单掉帧形成了可复用的方法：

1. 从源码与实测建立具体假设：hover 使菜单重绘，矩形内部距离和不可见图元仍有开销。
2. 分成独立补丁，每次只编译相关 C++ 对象并归档/链接；本次两轮分别为 9.17、9.64 秒。
3. 先检查结果等价，再谈性能。真实 CM4 GLES 上 241 组 shader 输入要求 RGBA8 字节
   完全相同、零容差，并用故意改色的负对照确认比较器有效；CPU 绘制另以 35 组用例
   核对不可见图元跳过、可见边框/阴影保留，详见验证工具（工程源码：`image/packages/noctalia/validation/README.md`）。
4. 固定输出缩放、桌面配置、壁纸、菜单和输入操作，停编译后重复测量。报告实际指标：
   本次是 GPU render 时间/提交任务，从约 22 ms 降到约 14.7 ms，不能换称屏幕 FPS。
5. 请求实体屏幕观察。用户该轮确认菜单“明显流畅了”；其他功能按独立证据判断，
   音频、门户等后续实测见[桌面对比记录](../desktop/labwc-shell-comparison.md)。
6. 将改动整理成配方中的聚焦补丁，生成一次 `.deb` 和回执，后续镜像直接复用缓存。

通用 shader 修改可以复用于不同 GPU，但每种目标驱动仍需运行像素等价验证和相同条件的
交互测量；CM4 V3D 的通过结果不能替代 Rockchip GPU 验证。当前数值与功能证据见
[桌面对比记录](../desktop/labwc-shell-comparison.md)，板型设计见[多平台设计](../../project/board-design.md)。
