# CM4：uConsole 黑屏与无网络的排查边界

> 同一套 CM4 软件曾黑屏也曾显示，根因未隔离；DSI 写成功和背光亮都不能证明面板正常。

## TL;DR

- 官方与 ak-rex 社区镜像是用户已验证的正常显示基线，不把工程失败外推为它们必然失败。
- 先保留 SD 日志与启动输入，再分开验证网络、PMIC/USB、显示；电源灯亮和无路由租约都不能定位启动阶段。
- 不能以 DSI connected、写入返回 0 或 framebuffer 截图判定实体屏幕成功，必须显示已知内容并观察。
- CM5 对照后 CM4 恢复时，内核/面板/配置/overlay 未变；供电状态、复位与接触问题仍是未隔离假设。

## 已知正常镜像基线

用户确认官方镜像与 ak-rex 镜像均可正常点亮本屏。参考源码、参考二进制、实际安装软件
必须区分：版本号相同不能证明二进制对应所查提交；原始分支日志也不能确定最终初始化表。
面板通用 compatible `cw,cwu50`、旧分支日志和失败读取的全零缓冲区都不构成物理型号证据。

## 无网络启动的最小诊断方法

1. 卡返回后先只读检查 FAT，ext4 用 `ro,noload`，保存日志、内核/DT/initrd/配置哈希和实际 root 引用。
2. 核对预置账户、SSH、私有 Wi-Fi keyfile 权限/自动连接、rfkill 与天线选择，不把凭据写入知识库。
3. 无新 journal 只说明没有已保存的 Linux 证据；固件、早期内核与硬件连接仍待区分，必要时用串口。
4. 先用已验证载板配置建立网络路径，再逐项恢复 uConsole 专用设置，避免一次改变多个变量后认定根因。

**历史观察：** 通用载板配置与换成 DWC2 都只枚举 Genesys hub；加板级 overlay 后出现
AXP221 与 `1eaf:0024` HID。USB 供电、无电池时也可枚举，所以电池不是键盘枚举前提；
这一相关性仍不能单独证明具体哪路 PMIC 电源使键盘可用。网络正常不等于显示或输入通过。

## 显示测试与不能采用的替代判据

| 试验观察 | 可支持的结论 | 不能支持的结论 |
| --- | --- | --- |
| 原模块 ID 读取及后续写入 `-110` | DSI 通信失败 | 面板型号、物理缺电原因 |
| 跳过 ID 后 212 次写成功，实体仍黑 | 主机传输完成 | 面板收到并正确执行命令 |
| 增加 DCDC3/VCI 1.8 V，仍失败 | 此配置未隔离解决故障 | 显示轨已实测有电或无电 |
| LP 命令/120 ms 复位延迟/新表完成仍黑 | 被测变更未满足可见画面判据 | 官方完整镜像不能正常工作 |
| DRM connected/enabled、桌面截图有内容 | 主机合成/输出状态 | 实体屏幕正常 |

新表 189 次有效写入与旧表 211 项来自参考源码；不能遗漏表后 sleep-out/display-on/TE
及共用退出睡眠顺序。工程恢复了完整序列，23 项参考注释命令仍禁用；诊断无 ID 修改未形成生产修复。
不要为验证面板反复启动占用 DRM 的桌面。先停桌面，用匹配内核的单模块与已知 framebuffer
色条验证；输出不正确就卸载迭代，避免整棵模块构建。

## 显示供电证据

**原理图事实：** 官方 Mainboard V3.14/V5 将 `SYS_1V8`、`CM_1V8`、`DISP_1V8` 相连；
CM4 adapter 引出模块 1.8 V，DCDC3 也连到该网络。ALDO2 提供 `DISP_3V3`。
所以 CM4 overlay 缺 VCI 消费者不等于物理缺 1.8 V，DCDC3 消费者数为零也不等于电源关闭。

| 主板 J302 引脚 | 信号 | 需要的电气证据 |
| --- | --- | --- |
| 18/19 | DISP_1V8 | 连接器处实际电压 |
| 38/39 | DISP_3V3 | ALDO2 供电实际电压 |
| 24 | LCD_RESET/GPIO8 | 初始化期间拉低/释放波形 |
| 35/36、28/29 | LEDA、LEDK | 独立背光路径，不能替代逻辑供电检查 |

公开 CM4 adapter 引出 DSI1 四对数据与时钟，与四通道配置一致；实际板卡版本、导通与波形
未测。初始化失败后的 GPIO8 低可能来自 `cwu50_power_off()` 错误清理，不能推断之前没释放复位。
原理图来源为 [clockworkpi/uConsole](https://github.com/clockworkpi/uConsole)
树 `53a05efca806ca024aab4fbfd28a680688c2541c`，已核对 PDF Git blob；不以寄存器编程值冒充测量。

## CM5 对照测试后的 CM4 恢复

**设备观察：** 2026-10-18，用户确认启动 `f5bf4e424aee42a2bed84b5e568c60df`
的 CM4 可见内容；`6.18.57-v8-uconsole`、DSI 720×1280、背光 9/9，LightDM 未运行。
已安装模块 srcversion 为 `A60EE00AB7A61904BD32189`，失败单元和固件保护标志均为零。
以下输入与上次黑屏一致：

| 输入 | SHA-256 |
| --- | --- |
| Image | `9bff54d79b1b2277d2ebe14067101174daec7bae1c936ff9d0d11b557b8b9875` |
| 压缩面板模块 | `0edab0f2e03a7727624de0960d467a2affb5900aaf19e2364e2e9f932d5ebd4a` |
| config.txt | `8043ca77826e05b3dd66fbf071d6571b8eba60a502f66a111b2ded826d8f996c` |
| overlay | `b2a1e6e4aad2b07f9a0520e9e0304bb39eb7950f663f83c6149829884efd017e` |

上次失败有 DSI turnaround/`-110`，此次无该超时。准备的新 CM4 模块此前并未加载，
不能把恢复归因于它。CM5 热替换的单模块验证见[受控对照](../display/cm5-panel-module-comparison.md)。

**结论与未知：** 显示软件可工作，但原失败根因和该次恢复的重复性未建立。换核心板同时
改变供电/复位状态与连接接触，不能单独归因完全断电、初始化表或未插紧；没有永久写坏 IC 的证据。
软件读出的稳压器值与用户断电报告不证明显示电源轨曾实际降到零。

## 参考内核对照与恢复方法

ak-rex 归档 `6.12.94-v8+` 的 CM4 内核及其 overlay 在当次硬件状态也出现 ID/写入 `-110`；
原驱动忽略写错误可使加载持续数分钟。这说明失败不限于 6.18 移植，不能据此推翻已知正常镜像。
两轮曾有网络失联，日志无法确定原因；网络不可达既不等于关机，也不证明 panic。

试验采用独立内核/initrd/配置，保留工程 6.18。恢复机制必须覆盖被测操作完整时段，
不能只因初始 SSH 成功就取消。tryboot 只选择下次复位入口；timer 不覆盖进入 PID1 前卡死，
看门狗“已配置”也不证明发生过复位。恢复后须核对正常内核与配置哈希。

原始只读 SD 采集在忽略的 `image/work/cm4-boot-failure-20261017/`；恢复身份和日志在
`~/.cache/uconsole-cm4-panel/recovery-20261018/`。逐次过程留在证据/Git 中，后续按本文固定
SD 与软件、区分热重启和电源轨真正掉电，并以实体画面作为结论依据。
