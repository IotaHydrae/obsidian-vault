# Linux USB-C：区分供电能力、协商档位和实际功率

> 系统报告的供电上限或协商电流不是实际充电功率；只有匹配端口的实时电压、电流才能支持相应测量结论。

## TL;DR

- 分清端口能力、已选择的合约和实时消耗三个层次。
- 先确认 source/sink 角色、对端及采样时刻，避免读到其他设备或电池数据。
- 没有合适的传感器和接口时，应明确“不可观测”，而不是用上限代替实测。

| 读数 | 含义 | 不能据此推断 |
| --- | --- | --- |
| Source PDO / 供电能力 | 源端可通告的档位 | 当前选中档位或实际输出 |
| RDO / 合约信息 | 连接双方协商的请求或约束 | 设备持续按该电流消耗 |
| 电压、电流传感器 | 在其测量位置和时间的观测 | 未对应端口的其他支路功率 |

5 V × 3 A = 15 W 是一个能力组合的算术上限，不保证某设备正在消耗 15 W，也不能保证多个端口同时各达到该值。线缆、系统共享预算与设备需求还会限制结果。

## 检查方法

```bash
ls -l /sys/class/typec/
ls -l /sys/class/power_supply/
```

这些接口是否存在、暴露哪些属性取决于控制器、驱动和内核。结合设备拓扑确认哪一项属于目标端口；`power_supply` 中可能是电池或其他电源。标准属性的单位也必须核对，例如电压和电流常用微伏、微安。

只有在确认字段意义、方向和时间对应后，才计算 `P = V × I`。设备已断开、partner 不完整或合约未暴露时，不能从缺少字段推断握手失败或读出实际功率。

需要同时观察 PD 协商与真实电压、电流，而软件接口不足时，可用支持相关协议和额定规格的串接仪表；测试时记录位置与线缆，仪表本身也属于测量路径。

参考：[Linux Type-C 接口](https://docs.kernel.org/driver-api/usb/typec.html)、[Power Supply 类](https://docs.kernel.org/power/power_supply_class.html)。
