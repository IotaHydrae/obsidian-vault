声明式宏最核心的逻辑是**模式匹配**。它看起来有点像 `match` 表达式，但它匹配的是 Rust 的**源代码标记 (Tokens)**。

为了理解它，我们来尝试写一个简化版的 `my_vec![1, 2, 3]` 宏。这个宏的目标是接收一系列元素，并自动生成创建一个 `Vec` 并推入这些元素的代码。

宏的基本结构 🏗️

```rust
macro_rules! my_vec {
    ( $( $x:expr ),* ) => {
        {
            let mut temp_vec = Vec::new();
            $(
                temp_vec.push($x);
            )*
            temp_vec
        }
    };
}
```

这里面有一些特殊的符号，我们先关注最关键的**匹配部分**：`$( $x:expr ),*`

- `$x:expr`：表示匹配一个**表达式**（比如一个数字或变量），并把它命名为 `$x`。
    
- `$( ... ),*`：这是一个重复模式。它告诉 Rust：“匹配括号里的内容，并且这些内容之间用**逗号**分隔，可以重复**0次或多次**”。

### 思考时间 🤔

如果我们调用 `my_vec![1, 2]`，根据上面的定义：

1. `$x` 第一轮会匹配到什么？
    
2. 代码块中 `$( temp_vec.push($x); )*` 这一部分最终会被展开成几行 `push` 代码？
    

你可以试着推测一下展开后的样子。

> 1. 数字 2. 两次

回答得非常准确！

当调用 `my_vec![1, 2]` 时：

1. **匹配结果**：`$x` 第一轮匹配到 `1`，第二轮匹配到 `2`。
    
2. **展开效果**：重复模式 `$( ... )*` 会根据匹配到的次数进行展开，因此会生成两行 `temp_vec.push(...)`。
    

展开后的代码逻辑如下：

```rust
{
    let mut temp_vec = Vec::new();
    temp_vec.push(1); // 第一轮展开
    temp_vec.push(2); // 第二轮展开
    temp_vec
}
```

### 进阶：处理多种模式 🔀

声明式宏最强大的地方在于它可以像 `match` 一样处理**多个分支**。比如，如果我们希望 `my_vec![]`（不带参数）也能工作，我们可以增加一个空匹配分支。

此外，Rust 的宏还可以捕获不同类型的“片段选择器”（Designators）。除了我们用过的 `expr`（表达式），还有：

- `ident`: 标识符（变量名或函数名 📛）
    
- `ty`: 类型（如 `i32`, `Vec<u8>` 🧬）
    
- `path`: 路径（如 `std::collections::HashMap` 🗺️）
