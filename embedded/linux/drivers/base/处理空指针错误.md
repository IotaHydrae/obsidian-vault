# Linux 错误指针：`ERR_PTR`、`IS_ERR`、`PTR_ERR`

> 先确认被调用 API 的错误约定：有的返回 `NULL`，有的返回编码错误的指针，不能混用检查方式。

```c
static struct thing *setup(void)
{
    struct thing *item = allocate_thing(); /* 假设该 API 失败返回 NULL */
    if (!item)
        return ERR_PTR(-ENOMEM);
    return item;
}

static int probe(void)
{
    struct thing *item = setup();
    if (IS_ERR(item))
        return PTR_ERR(item);
    /* 使用 item */
    return 0;
}
```

`ERR_PTR(error)` 将负错误码编码为指针，`IS_ERR(ptr)` 检查错误指针，`PTR_ERR(ptr)` 取回错误码。只有 API 明确允许同时返回空指针和错误指针时才使用 `IS_ERR_OR_NULL()` 并分别处理两者。示例是伪代码，不对应特定分配器；真实驱动还需处理资源释放和 `-EPROBE_DEFER` 等错误。
