既然我们决定从**派生宏 (Derive Macros)** 开始，那我们先来看看它最神奇的地方：它能让你在不手写任何逻辑的情况下，赋予一个结构体某种“能力”。

在 Rust 中，派生宏是通过 `proc_macro_derive` 属性定义的。它的输入是你的结构体或枚举的定义，输出则是为该类型自动生成的 `impl` 代码块。

### 它是如何工作的？⚙️

当你写下 `#[derive(Hello)]` 时，编译器会把整个结构体的源代码作为一串**标记流 (TokenStream)** 传给宏函数。宏函数就像一个“代码编译器”，它会分析这些标记，然后吐出新的代码。

为了处理这些标记流，我们通常需要两件利器：

1. **syn**：一个将源代码标记解析成易于操作的“语法树”的库（比如能让你直接拿到结构体的名字、字段名）。
    
2. **quote**：一个将 Rust 代码转换回标记流的库，让你能像写普通代码一样写宏的输出。

### 核心流程 🛠️

一个典型的派生宏函数长这样：

```rust
#[proc_macro_derive(Hello)]
pub fn hello_derive(input: TokenStream) -> TokenStream {
    // 1. 解析输入：把 TokenStream 变成一个结构体对象
    let ast = syn::parse(input).unwrap();

    // 2. 构建输出：生成 impl Hello for ... 代码
    impl_hello_macro(&ast)
}
```

### 设想一下 💡

假设我们有一个结构体：

```rust
struct User {
    name: String,
}
```

如果我们想为它自动实现一个 `hello()` 方法，打印出 "Hello, I am User"。

在这个过程中，宏需要从输入的代码中提取出哪个关键信息，才能生成 `impl User { ... }` 这一行？你会选择提取：

1. 字段的类型（如 `String`）
    
2. 结构体的名称（如 `User`）
    
3. 字段的名称（如 `name`）

> 2

完全正确！🎯 结构体的**名称**（如 `User`）是生成 `impl` 块时最关键的信息。

在过程宏中，我们使用 `syn` 库将输入的代码解析为一种树状结构（AST）。对于结构体，这个结构被称为 `ItemStruct`。

### 提取名称的逻辑 🔍

如果你在宏代码中解析了输入：

```rust
let input = parse_macro_input!(input as DeriveInput);
let name = &input.ident; // 这里就拿到了结构体的名字，比如 User
```

代码生成示例 ✨

```rust
let expanded = quote! {
    impl #name {
        pub fn hello(&self) {
            println!("Hello, I am {}", stringify!(#name));
        }
    }
};
```

这段代码会被转换回 `TokenStream` 并交给编译器。最终，编译器看到的就像是你亲手写了 `impl User { ... }` 一样。

### 深入一步：处理字段 (Fields) 🧬

大多数派生宏（比如 `serde` 的 `Serialize`）不仅需要知道结构体的名字，还需要遍历它的**字段**。

在 `syn` 的数据结构中，字段信息存放在 `input.data` 里面。假设我们要写一个更高级的宏，它能打印出结构体中**所有字段的名字**。

如果我们要从 `User { name: String, age: u32 }` 中提取出 `name` 和 `age`，你觉得在宏的处理逻辑中，我们需要对字段进行什么样的操作？

1. 仅仅获取结构体的总字段数。
    
2. 遍历（Iterate）结构体中的每一个字段并提取其标识符（ident）。
    
3. 只需要查看第一个字段即可。

> 2

完全正确！🎯 遍历结构体的**字段 (Fields)** 是实现复杂逻辑的关键。

在 `syn` 解析出的语法树中，结构体的数据被存放在 `input.data` 中。如果是普通的命名结构体（如 `struct User { name: String }`），字段信息会存放在 `FieldsNamed` 类型中。

### 提取字段的逻辑 🔍

我们可以通过迭代器拿到每一个字段的标识符（即字段名）：

```rust
let input = parse_macro_input!(input as DeriveInput);

// 假设我们已经确认这是一个结构体
if let syn::Data::Struct(data) = input.data {
    let fields = data.fields;
    
    // 提取所有字段的名称
    let field_names = fields.iter().map(|f| &f.ident);
    
    let expanded = quote! {
        impl #name {
            pub fn describe_fields() {
                #(
                    println!("字段名: {}", stringify!(#field_names));
                )*
            }
        }
    };
}
```

注意这里的 `# ( ... )*` 语法，它和声明式宏里的 `$( ... )*` 非常像，代表对集合中的每个元素重复生成代码。

### 宏的“三个盒子”模型 📦

开发过程宏通常涉及三个不同的 crate（项目包），这是初学者最容易困惑的地方：

|**盒子**|**名称**|**作用**|
|---|---|---|
|**1. 逻辑盒**|`my_macro_derive`|**必须**是 `proc-macro = true` 类型。这里存放复杂的解析逻辑。|
|**2. 定义盒**|`my_macro_traits`|存放宏要实现的 `Trait` 定义。|
|**3. 使用盒**|`my_app`|你的实际业务代码，调用 `#[derive(MyMacro)]`。|
**为什么逻辑盒必须是一个独立的 crate？** 因为过程宏在编译你的程序**之前**必须先被编译并运行，它本质上是编译器的插件。

### 总结与下一步 🏁

我们已经聊过了：

- **声明式宏** (`macro_rules!`)：模式匹配，简单高效。
    
- **过程宏 - 派生宏** (`derive`)：解析语法树，自动实现 Trait。
    

你现在对 Rust 宏已经有了很好的全局认识！你想最后了解一下哪方面的内容来结束这次学习？

1. **宏的调试技巧** 🛠️：怎么看到宏展开后的代码到底长什么样？（非常实用）
    
2. **属性宏简介** 🏷️：像 `#[tokio::main]` 这种修改函数的宏是怎么回事？
    
3. **实际演练建议** 🎓：如果我想自己动手写一个，从哪类题目练手比较好？


## #[proc_macro_derive(Hello)] 的完整示例

要写一个完整的过程宏示例，我们需要遵循 Rust 的规则：**过程宏必须定义在独立的 crate 中**。

我们可以构建一个简单的 `Hello` 派生宏。当你在结构体上标注 `#[derive(Hello)]` 时，它会自动生成一个名为 `hello` 的方法。

我们可以按照以下三个步骤来实现这个系统：

---

### 第一步：创建宏定义 Crate (`hello_macro`) 📦

首先，创建一个名为 `hello_macro` 的文件夹。在它的 `Cargo.toml` 中，必须声明这是一个过程宏库。

**`hello_macro/Cargo.toml`**

```toml
[package]
name = "hello_macro"
version = "0.1.0"
edition = "2021"

[lib]
proc-macro = true  # 核心：声明这是过程宏

[dependencies]
syn = "2.0"       # 将 TokenStream 解析为语法树
quote = "1.0"     # 将语法树转回 TokenStream
```

**`hello_macro/src/lib.rs`**

```rust
use proc_macro::TokenStream;
use quote::quote;
use syn::{parse_macro_input, DeriveInput};

#[proc_macro_derive(Hello)]
pub fn hello_derive(input: TokenStream) -> TokenStream {
    // 1. 解析输入
    let input = parse_macro_input!(input as DeriveInput);
    
    // 2. 获取结构体名称
    let name = &input.ident;

    // 3. 构建输出代码
    let expanded = quote! {
        impl #name {
            pub fn hello(&self) {
                println!("Hello, I am {}!", stringify!(#name));
            }
        }
    };

    // 4. 转回 TokenStream
    TokenStream::from(expanded)
}
```

---

### 第二步：创建使用宏的项目 (`example_app`) 🚀

在同一个目录下创建你的应用项目，并在 `Cargo.toml` 中引用上面的库。

**`example_app/Cargo.toml`**

```toml
[dependencies]
hello_macro = { path = "../hello_macro" }
```

**`example_app/src/main.rs`**

```rust
use hello_macro::Hello;

#[derive(Hello)]
struct User;

#[derive(Hello)]
struct Pet;

fn main() {
    let u = User;
    let p = Pet;
    
    u.hello(); // 输出: Hello, I am User!
    p.hello(); // 输出: Hello, I am Pet!
}
```

### 调试与观察 🔍

过程宏最让人头疼的是“看不到生成的代码”。为了解决这个问题，Rust 社区有一个非常有用的工具叫做 `cargo-expand`。

如果你安装了它，运行 `cargo expand`，你就能看到编译器眼中被宏“炸开”后的样子。
