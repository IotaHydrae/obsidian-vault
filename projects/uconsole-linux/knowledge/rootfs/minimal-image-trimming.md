# 精简镜像时如何保留运行和维护能力

> 从功能契约推导包清单，再用依赖模拟和真实功能验收；按名字通配删除容易破坏隐式依赖。

## TL;DR

- 区分 rootfs、构建宿主、运行设备，裁剪规则不能跨对象直接套用。
- `--no-install-recommends` 后仍需显式补齐所需可选组件，尤其固件、蓝牙音频、portal 与维护工具。
- 包标称大小、文件实占、镜像长度和运行内存分别测量，不能混加收益。
- CM5 IO Board 先保持 stock 硬件支持；本次没有批量裁剪内核模块或删除必要用户态。

## 包集裁剪

先列保留功能和维护入口，找出直接安装根包及其 Depends/Recommends。
在目标 rootfs 中进行 APT 模拟，确认移除闭包没有牵连保留组件。
元包移除后先确保保留组件被正确标记，避免 autoremove 将其当孤儿。
不要按 `*-dev`、`lib*` 或整个驱动目录做无依据清理。

把临时编译依赖与运行依赖分开；只清理本次拥有的依赖不能推导为宿主也可卸载。
打包在一起的 SDK 与运行文件如需精确裁剪，优先维护可审计的包规则；
dpkg path-exclude 会影响升级/重装与文件核验，必须核对例外，不能忽略所有 missing。
本仓库预编译包有局部文档保留策略，以免 Base 的默认排除丢掉许可证。

## 内核裁剪

先区分全量重编、编译并行、缓存失效和真实模块数量成本。
`lsmod` 只反映当前加载，不能作为全部支持硬件白名单；恢复介质、USB 调试线和可热插拔外设可能尚未加载。
内建驱动的缺固件告警也不会因只删模块而消失。
项目配置使用独立 fragment，olddefconfig 后检查 y/m/n 的实际结果与依赖，不编辑固定上游 defconfig。

## 体积口径

| 指标 | 测什么 | 限制 |
| --- | --- | --- |
| Installed-Size | 包元数据声明的安装量 | 不跟随手动删文件、排除规则实时变化 |
| du 实占 | 文件系统已占块 | 硬链接、压缩、稀疏与 xattr 影响 |
| stat 长度 | 镜像/文件逻辑长度 | 包括空闲和预留分区空间 |
| RSS/PSS | 运行时内存 | 不能从磁盘减少量推导 |

## 验收边界

包审计无未配置项、依赖满足，离线检查最终镜像的所需文件和权限。
上板再验证维护登录、网络、预定 IO、启动介质及升级恢复；没有实际执行的项保留未知。
对 headless 配置不要求桌面功能，但不能据此删去未来 IO 开发明确需要的通用驱动。
本仓库 package 复用契约见 [包身份与 ABI](../build/userspace-package-reuse.md)，
镜像范围见 Ubuntu Base（工程源码：`image/ubuntu-base/README.md`）。
