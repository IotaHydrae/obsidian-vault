# 构建工具入口、失败语义与知识审计

> 工具应让选择、执行和结果各自清楚；一个入口的成功退出只承诺它文档化的职责。

## TL;DR

- 菜单只保存合法选择，构建入口委托现有后端；避免多套入口各维护一份构建逻辑。
- `--help` 和只读预检不应要求构建权限；失败保留明确退出语义，不用正常输出掩盖错误。
- 离线文件准备、镜像生成、写入物理介质分别操作；工具不隐藏部署动作。
- 知识库审计适合检查链接、索引和结构，技术事实仍需结合当前源码复核。

## 本仓库已有机制

构建菜单（工程源码：`tools/build_menu.py`）将选择校验、交互选择与运行构建分开，
`lunch` 保存选择，`run_build()` 委托 Makefile 目标。镜像入口（工程源码：`scripts/image_build.py`）
通过 `image_profiles` 解析板型与系统组合，再将实际工作交给 rootfs 后端。
新增板型应扩展已有元数据和后端契约，避免另写一个独立构建总脚本。

根 Makefile（工程源码：`Makefile`）服务于人工构建和验证，
Makefile.agent（工程源码：`Makefile.agent`）承载机器交接接口；schema 和退出行为见
[docs/agent.md](../../project/agent.md)。稳定 JSON 接口的字段与退出码需要一同维护，不能让调用者解析人类提示语猜测状态。

候选内核工具（工程源码：`tools/kernel_candidate.py`）默认预览，显式 apply 才向离线
rootfs 添加候选文件；不选择启动项。这个边界让准备结果可检查，不能把“文件已放好”描述成“已部署并可启动”。

## 可迁移的工具经验

在工作开始前验证参数、板型、依赖和可写输出，尽量一次报告全部缺失依赖。帮助解析先于 root 检查；对于确实需要权限的动作，在具体执行边界报错。

命令失败向上传递；不要在构建后追加打印语句而丢失实际退出码。分组准备多个产物时可汇总失败项，但只有全部必需产物满足契约才发布完成状态。临时文件与挂载由创建者清理。

机器报告使用稳定字段和 schema 版本，诊断信息放 stderr 或明确字段。涉及敏感输入时输出用于定位的类别与字段名，避免回显密码、账户哈希、网络配置或整个 spec。

## 知识审计的可迁移范围

本仓库的 knowledge_audit.py（工程源码：`tools/knowledge_audit.py`） 自动检查本地链接、索引、重复二三级标题、首屏 TL;DR 与严格少于 300 行的篇幅。检查限定到知识目录，不扫描上游源码和缓存；输出文件、行号、规则类别和退出状态。

本库篇幅是用户明确要求，因此达到 300 行即失败；过时或敏感内容由人工复核，不冒充已自动验证。提取器过滤 backtick/tilde 围栏和行内代码，避免将示例链接当成正文引用。

运行 `make knowledge-check`；CLI 参数与退出码见工具说明（工程源码：`tools/README.md`）。它是人工检查入口，不新增稳定 JSON 状态接口。审计通过只证明所列机械条件，事实、锚点与外部证据仍需按知识库复核技能（工程源码：`skills/knowledge-base-review/SKILL.md`）核对。
