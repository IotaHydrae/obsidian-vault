# 启动计时：时钟域、起点与可用终点

> 先定义事件与时钟，再比较耗时；来自不同原点的时间不能直接相加。

## TL;DR

- 上电、固件开始、Linux 零点、PID1、进程创建、首帧和可交互各是不同事件。
- 主机串口接收时间包含传输延迟；SSH 回连时间包含关机与连接重试。
- 用共同事件锚点对齐时钟，并记录误差、缺段和探针开销。
- 本仓库既有 CM4 数值仅适用于其记录的系统、介质与启动方式。

## 常见时间源

| 来源 | 适合比较 | 主要限制 |
| --- | --- | --- |
| 外部上电计时/视频 | 物理启动与可见画面 | 帧率、触发点、供电与拍摄误差 |
| 固件串口自报计时 | 固件内部阶段 | 原点可能不覆盖复位前缀 |
| printk/dmesg | Linux 内核事件 | 日志级别、缓冲丢失、打印时序影响 |
| journal monotonic | 当前 boot 的用户态事件 | 早期导入日志可能按接收时刻收录 |
| /proc PID stat | 进程创建 | tick 分辨率，不代表应用 ready |
| 主机 monotonic UART RX | 外部连续记录 | 波特率、USB 批量与调度延迟 |

墙钟受校时影响，不宜直接计算短阶段耗时。monotonic 不因设置墙钟跳变，
但跨设备时钟的漂移、速率和基准仍需说明。

## 对齐方法

选择可以在两侧识别的同一个事件，例如带唯一标识的日志或受控触发。
记录目标时间、主机接收时间与采集分辨率；不能假设一条串口消息零延迟。
如果只得到 Linux 后半段，就报告 Linux 后耗时，不能补猜固件部分。

`systemd-analyze time` 可能没有独立 initrd 时间戳，kernel 字段因此包含 initramfs。
固件支持的时间戳字段也因平台不同而异。先核对实现再拆阶段。
嵌套 initcall/probe 的时间相互包含；并行单元也不能直接求和。

## 可用终点的判据

SSH 认证/执行命令、端口监听、HTTP 响应、浏览器导航、FCP、合成器帧、物理显示和用户输入分别验收。
一次 screencopy 只证明抓到的合成画面，不必然证明面板已呈现。
`Started` 对 simple/notify/dbus 服务的含义不同，不能为缩小数字提前报告 ready。

## 报告与比较

每个样本写清 boot ID、冷上电或热重启、板型、介质、内核、配置摘要、起止事件及时间源。
比较前控制缓存、外设、网络和探针条件；保留原始样本、异常与未测阶段。
数据不足时报告观察，不将一次差值当稳定收益。
