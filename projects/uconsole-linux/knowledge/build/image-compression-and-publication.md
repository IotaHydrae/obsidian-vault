# 镜像压缩与产物发布

> 压缩是对已生成镜像的打包操作；它不证明镜像可启动，也不应隐含刷写或重新构建。

## TL;DR

- 显式选择 `.img`，独立运行压缩工具；不自动选择目录中“最新”的未知产物。
- 保留解压后字节数；可选计算压缩文件 SHA-256，二者保护的属性不同。
- 输出和 sidecar 不覆盖已有文件，压缩失败清理本次临时文件。
- 本仓库新增 `tools/compress_image.py`，支持 zstd 与 Zip64，详见 工具说明（工程源码：`tools/README.md`）。

## 使用

```sh
python3 tools/compress_image.py <IMAGE.img> --dry-run
python3 tools/compress_image.py <IMAGE.img> --method zstd --level 3 --sha256
python3 tools/compress_image.py <IMAGE.img> --method zip --level 1
```

路径占位符需替换。Zip 路径仅使用 Python 标准库；zstd 需要主机命令。
工具拒绝 `/dev` 与非普通 `.img` 输入，不打开块设备，不删除原镜像。
默认输出 `<IMAGE.img>.zst` 或 `.zip`；自定义输出使用 `--output`。

## 回执与完整性

`<ARCHIVE>.rawsize` 记录裸镜像字节数，适合容量预检；它不能证明解压内容正确。
`--sha256` 产生 `<ARCHIVE>.sha256`，摘要覆盖压缩包；裸镜像身份仍以原构建回执为准。
分发方需要同时保留构建 receipt、裸镜像摘要与压缩包摘要，避免把同名文件当同一产物。
校验来源本身也必须可信，不能用包内自带摘要单独证明真实性。

## 失败与原子边界

临时文件创建在输出目录，权限 0600；压缩成功且源文件元数据未变化后准备 sidecar。
工具通过不覆盖的链接发布 sidecar，最后发布压缩包；异常清理已发布的本次文件和临时文件。
文件级原子发布不等于多个文件的断电事务；断电后残留需核对，不自动把 archive 存在当完成。
源文件并发修改的元数据检查可发现常见竞争，不代替对输入快照的强隔离。

## 性能与适用边界

压缩比、耗时、CPU 和解压速度取决于镜像内容、级别与主机；不迁入另一硬件的性能数字。
Zip64 允许大文件，但接收端工具兼容性仍应检查。
小夹具的解压字节比较验证工具的无损契约，完整系统的离线检查使用未压缩 `.img`。
构建、打包、离线检查、物理写入与实际启动分别记录。
